## Git commits

When creating git commits:

- Use English only.
- Use lowercase only.
- Keep the message short and direct.
- Use an imperative-style summary when possible.
- Do not use emojis.

## Project documentation

- Before changing a feature, read the relevant documentation in `docs/` to understand its intended behavior and design decisions.
- For watch-history changes, read `docs/watch-history.md`, including when changing viewing dates, episode grouping, chronological ordering, or interactions with watch state.
- Compare the documentation with the current implementation. If they disagree, raise the discrepancy in chat rather than assuming either one is automatically correct.
- Do not create, edit, rename, or delete project documentation as part of implementation work unless the user explicitly authorizes those documentation changes.
- Report any necessary documentation corrections or suggested additions exclusively in chat for the user's review. Do not apply them or create separate proposal files without explicit authorization.
- Keep documentation focused on behavior and design decisions; do not automatically add implementation details, visual specifications, or development logs after each change.
